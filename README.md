# 小黑盒运营插件

这个插件让 MaiBot 用自己的人设在小黑盒逛帖、点赞、评论和发帖，可联动生活轨迹、游戏话题和绘图能力。它使用 MaiBot 官方插件 Runner、独立 SQLite 状态库和小黑盒客户端，不修改 QQ 主链数据。

## 人设

评论、回复和帖子默认使用 MaiBot 主配置里的昵称（`bot.nickname`）和人格设定（`personality.personality`），和 MaiBot 在 QQ 上回复时用的是同一份人设；在 WebUI 改人设或切换人设方案后，插件最多一分钟内跟上，不用重启。想让小黑盒上的身份或口吻不一样时，在配置页「内容与插件联动」里填写“小黑盒人设（可选）”，填写后只影响本插件。两者都读不到时使用一句中性人设。插件为此声明了 `config.get` 能力，只读取这两个字段。

## 默认运营状态

发布版默认是 `enabled = true`、`mode = "auto"`、每天最多主动发 1 帖，并使用 Steam + PC 游戏作为默认发帖目标。首次安装或更换账号后，应先确认登录状态、社区目标和内容边界；需要只读验收时，把运行模式改成 `dry_run` 或把每日额度设为 0。

主要限制包括每日发帖/评论/通知回复配额、账号级冷却、社区白名单、内容重复键、敏感/技术内容拦截、发送结果未知状态以及认证失效和限流退避。

## 配置说明

0.7.0 早报先读取公开原文及首次发布日期，再独立审校事实句和简评；没有原文时不会改用搜索摘要充当证据。记录具体事件对象、版本和阶段，按事件处理同日/近3日重复，并兼容旧草稿历史。数字必须与指标名、评测主体、条件、状态一起核对；每条只允许同一事件，计划开放与已提供下载不能互换。原文引用使用唯一来源ID，程序再检查逐字引句和时间；通过审校的正文才可进入配图与发帖，正文改动会使核验凭据失效。原文被网站拒绝、日期不明或合格新闻不足时，宁可暂缓/跳过。模型审校仍有判断边界，推荐继续使用草稿模式检查。

0.6.2 增加「自动运营额度 → 启用日常发帖」独立开关。关闭后跳过日常帖生成、配图、发布及发送前失败重试；早报、浏览、点赞和评论继续按各自设置运行。重新打开即可恢复，仍受每日主动发帖数和时间窗口限制。日常配图现在读取宿主真实昵称，使用完整生活场景插画，不要求账号栏、社交界面、点赞数或文字卡片，帖子标签也不再硬编码 maibot。

MaiBot WebUI 的插件配置页会显示每个字段的中文用途说明。推荐流浏览间隔默认是 600 秒（10 分钟），这是本插件为新用户提供的推荐值，不是小黑盒官方固定检查时间；可以根据账号活跃度、请求频率和模型额度自行调整。实际间隔在该值的 0.5–1.5 倍之间随机，每次按推荐流顺序点开 2–4 篇，大多只看不评；评论和点赞只给符合游戏筛选的帖子，当天的评论额度会摊到剩下的浏览场次里，不会集中在上午用完。点赞默认每天最多 3 个（`likes_per_day`），同一帖子只赞一次。插件重启后第一次浏览会推迟 2–15 分钟。联动「生活频率」时，她在睡觉或小睡就不逛也不发帖。`auto` 只有在插件启用、每日发帖数大于 0 且至少选择一个发帖目标时才会真实发帖；`dry_run` 只生成计划，不产生小黑盒写入。为控制活跃时段，新安装默认只在服务器本地时间 08:00–23:00 浏览推荐流和主动评论、10:00–22:00 主动发帖；两个时间窗口相互独立，时间间隔和时间窗口都可以在配置页修改。起止时间相同表示全天，结束时间早于开始时间表示跨午夜。

私信功能不属于当前发布范围，默认关闭。小黑盒私信发送依赖独立的客户端聊天界面，当前没有稳定、可复用的公开发送契约；插件不会把私信误判成评论，也不会盲目重试发送。未来方案和取舍见 [私信方案记录](docs/PRIVATE_MESSAGE_OPTIONS.md)。

主动运营默认 fail-closed：`community_allowlist` 默认是“PC 游戏”和“盒友杂谈”，只允许在游戏相关社区筛选和互动；`post_topic_ids` 为空时不主动发帖。配置页使用中文选项，插件会在发送前按准确名称查询小黑盒并解析内部 topic ID，不要求用户手工填写数字。

社区配置限制：白名单最多选择 10 个社区；配置页提供两个发帖目标下拉框，因此单条主动帖子最多选择 2 个社区或话题，这是小黑盒发帖接口的分区限制。两个目标即使选成一样，发送前也会自动去重。发帖目标解析失败时会跳过本轮发送，不会把内容发到不确定的分区。旧版配置中的数字 ID 仍可读取，旧版逗号分隔字符串会自动迁移到两个目标选项。

评论回复会先读取原帖标题、正文和收到的评论，再交给内容生成器，因此在自己发布的帖子下回复时会围绕该帖内容作答；回复时优先接对方评论的话，原帖只作背景。当前已支持小黑盒通知中心里的提及、评论和楼中楼回复；私信保持关闭。当前开发状态和已知限制见 [项目状态](docs/PROJECT_STATUS.md)。

## 每日 AI 早报

配置页「每日 AI 早报」默认关闭。开启前需要在 MaiBot 里配好统一联网服务（模型配置里的 `web_search` 任务），插件不保存任何搜索 Key。

- 时间：服务器本地时间 `post_time`（默认 08:00）开始搜索、写稿和审校，完成后私聊老板。默认不因生活作息晚起而推迟；可开启 `respect_sleep` 跟随睡眠。`deadline_time`（默认 11:00）只限制生成重试，已经送达的待确认稿可在当天确认。一天最多一帖。
- 选新闻：按配置的搜索词搜索（`{date}` 换成当天日期），丢掉没日期、超过 36 小时、命中屏蔽词、近 3 天讲过的，同一网站最多 2 条；不到 3 条当天放弃。模型挑 3–5 条，插件读原文后让模型写成早报合集，结尾加一句她的看法。
- 核查：筛掉来源未核实的站点和二次资讯汇总页，优先官方原文与已识别媒体。事实中的数字、英文词须出现在资料里；感想不能编造使用经历。可报道科技/AI 人物任免、公开声明和影响企业的已确认事件；负面个人事件或人事变动必须提供官方正文中的逐字引句，不把辞职写成开除。核查后少于 3 条则重试，仍不足就跳过。配文和老板草稿均保留来源链接。
- 配图（0.6.1）：把 3–5 条核查后资讯排成一张 1080 像素宽的长图，含日期、来源、事实和简评；中文直接排版，与正文使用同一份事实句。“使用报道配图”会读取公开文章分享图并标出处，没有合适照片就用原文摘录卡。这是带出处的摘录排版，不伪装为网页截图；不截取登录后内容。照片失败仍能生成文字长图，排版失败降级为纯文字。早报不再调用绘图模型，普通日常帖仍保留绘图联动。
- 渲染环境：Manifest 声明 httpx、cryptography 和 Pillow 的 Python 依赖，由宿主检查安装。另需可用中文字体（Linux 推荐 fonts-wqy-zenhei 或 Noto Sans CJK；Windows 可用微软雅黑）；字体缺失时会明确提示并生成纯文字草稿。
- 模式：`dry_run`（默认）只私聊预览，不上传、不发帖。基础设置和早报模式都设为 `auto` 后，**仍先私聊完整正文和一图流，老板当天在 QQ 私聊单独回复“可以发送”才发布**；“取消发送”放弃本稿。只接受配置的老板 QQ，本次确认不授权其他稿件，次日旧稿失效。重启后可继续确认已保存的原稿；重复确认不重复发帖。预览命令生成的草稿和历史 dry_run 草稿不能直接确认发送。
- 审核后发布使用保存的同一份正文、图片、分区和标签；配图上传失败时保留待确认状态，需要再次确认，不偷偷改成纯文字。发帖请求发出后不重发，结果及帖子链接私聊老板。生成失败最多试 3 次，每次至少隔 10 分钟；确认后的准备失败不自动重试发布。
- 私聊：需要在「基础设置」填写“老板 QQ”，并且这个 QQ 和 MaiBot 私聊过。`/xhh_news_preview` 可以马上生成一份草稿私聊老板，不占当天名额、不写发送记录。

## 登录

启用插件后，打开 MaiBot WebUI 中的“小黑盒运营”工作区即可直接生成二维码、扫码并轮询确认状态。二维码由插件内置的无依赖编码器生成，原始登录 URL 不显示在页面上。

也可以在 MaiBot 聊天中使用：

- `/xhh_login`：生成登录会话，并提示打开 WebUI 工作台扫码。
- `/xhh_login_check`：检查二维码状态。
- `/xhh_status`：查看插件运行模式。
- `/xhh_news_preview`：马上生成一份 AI 早报草稿私聊老板（不发小黑盒）。
- `可以发送`：老板在 QQ 私聊确认当天已经收到的待确认早报。
- `取消发送`：老板在 QQ 私聊放弃当天待确认早报。

凭证只写入 MaiBot 数据目录下本插件专用的 `credentials/`，日志不会打印 Cookie、Token 或二维码内容。

## 联动

生活轨迹通过插件市场的「生活频率」（ID：`org.orge-8.life-frequency`）提供的 `get_current_context` 只读 API 获取；身份参考图通过「自我身份档案」（ID：`org.mai-mai.self-identity`）的 `get_default_reference_image` 获取；主动帖子配图通过「麦麦绘图」（ID：`maimai-drawpic-plugin`）的 `drawpic_submit_v2`、`drawpic_request_v2`、`drawpic_task_v2` 和 `drawpic_image_v2` API 提交、恢复、轮询和读取。这三个插件现在都是可选联动，不会阻止小黑盒运营插件单独安装和加载。

未安装联动插件时，关闭“自动生成帖子图片”即可使用纯文本自动发帖；生活轨迹不可用时会退回服务器当前时间和已有设定；身份参考图不可用时会跳过参考图。插件市场不再把这三个联动插件声明为强制依赖，避免只想使用小黑盒自动发帖的用户被迫安装额外插件。

主动帖子的配图联动是可选增强：绘图任务明确失败、超时或图片上传失败时，插件会记录 `image_fallback` 审计标记并继续发布纯文字帖子，不会换新的 `request_id` 重复生成图片；只有实际附图成功时，读回核验才要求帖子包含图片。纯文字帖子和图文帖子都使用 `link_tag` 27。每日 AI 早报的配图规则不同，见上文。

API 名称的组成规则是“插件 ID + `@API(name=...)` 中的名称”。获取方法：先查看提供方插件 `_manifest.json` 的 `id`，再在该插件源码中搜索 `@API(name="...")`，最后按 `插件 ID.名称` 填入配置。当前插件已经填好可用的完整名称；只有更换提供方插件或 API 版本时才需要修改。

## 外部数据处理

主动帖子使用的生成图片和身份参考图（仅在插件 API 返回 base64 图片数据时读取）会通过小黑盒的上传接口发送到其使用的腾讯云 COS（通常为 `*.myqcloud.com`）以便在帖子正文中展示。插件不会根据插件 API 返回的任意本地 `path` 或 `file_path` 读取文件；需要传图的依赖应返回 base64 或图片字节。登录凭证仍只保存在 MaiBot 数据目录的本插件专用目录中。

开启每日 AI 早报后，搜索词和新闻网址会交给 MaiBot 的统一联网服务，认可的公开原文会经无凭证 HTTPS 请求取得，正文和公开新闻历史交给模型写稿及独立审校；网页内容只当资料，不执行其中的指令。草稿、来源链接、配图和发帖结果通过 `chat.get_stream_by_user_id`、`send.text`、`send.image` 私聊“老板 QQ”；没填老板 QQ 时不发私聊，也不能进入早报正式发送流程。待确认的正文、配图和目标保存在本插件持久数据目录 `news_drafts/`，不会因替换插件代码丢失；只有确认后才向小黑盒上传图片和正文。

## 验证

插件目录的测试覆盖 SQLite 幂等、内容边界、通知解析、绘图 API、媒体签名、Runner 加载，以及早报的筛选、核查、调度、只发一次和中途重启收尾。真实账号验收必须先保持低额度，并确认发帖/评论读回后再扩大范围。

## 安装与发布

插件仓库根目录必须保留 `_manifest.json`、`plugin.py`、`LICENSE` 和 `README.md`。发布版本时，Git tag、GitHub Release 和 `_manifest.json` 的版本号必须保持一致。插件市场提交方式参见 MaiBot 官方“发布插件”文档。

## 当前发布范围

- 已纳入：扫码登录、跟随宿主人设、推荐流不定时浏览、游戏话题筛选、点赞、图文发帖、评论和楼中楼回复、配额/冷却/幂等/读回核验、生活轨迹和生图插件联动。
- 默认开启：低额度真实自动运营，默认每天最多发 1 帖，目标为 Steam + PC 游戏。
- 默认关闭：私信功能、每日 AI 早报。真实写入前仍应确认账号登录、目标社区和生成内容符合预期。
- 暂不纳入：手机模拟器或实体手机代理。相关方案只记录在文档中，不会在插件市场版本中偷偷启用。
